# Skill Creator

새 스킬을 처음부터 만들거나, 기존 스킬을 개선하는 스킬.

## 스킬이란?

`.claude/commands/` 안에 `.md` 파일 하나 = 사람이 쓰는 커맨드 하나.
Claude가 해당 커맨드를 실행할 때 이 파일을 읽고 지침으로 삼는다.

---

## 스킬 파일 구조

```
.claude/commands/
└── skill-name.md       ← 이것 하나면 됨 (복잡한 경우 폴더로 분리)
```

### 파일 형식

```markdown
---
name: skill-name
description: 언제 이 스킬을 써야 하는지 + 무엇을 하는지. 구체적일수록 좋음.
---

# 스킬 제목

## 사용법
\`\`\`
/skill-name [인자]
\`\`\`

## 실행 순서
1. 단계 1
2. 단계 2
...

## 출력 형식
(결과물이 어떻게 생겼는지)

## 주의사항
(피해야 할 케이스, 하면 안 되는 것)
```

---

## 좋은 스킬의 원칙 (SKILL.md 기반)

**description에 "언제 써야 하는지"가 핵심**
- 나쁜 예: `"MongoDB 데이터를 분석한다"`
- 좋은 예: `"MongoDB 데이터 조회·분석이 필요할 때. 만족도, 이탈, 접속 데이터 분석 요청 시 반드시 사용"`
- description이 트리거 조건 → 애매하면 Claude가 스킬을 못 씀

**이유(Why)를 설명한다**
- 나쁜 예: `"반드시 JSON 형식으로 출력할 것"`
- 좋은 예: `"JSON으로 출력 → 이후 Notion MCP가 파싱하기 때문"`

**500줄 이하 유지**
- 길어지면 핵심이 묻힘. 참고 파일이 필요하면 `references/` 폴더로 분리

**MUST/NEVER 단발 금지**
- 이유 설명으로 대체. Claude는 맥락을 이해하면 알아서 잘 함

## 스킬 작성 프로세스

### 1단계 → 의도 파악

사용자에게 확인할 것:
- 이 스킬이 뭘 해야 하는가?
- 어떤 상황에서 쓰는가? (트리거 조건)
- 입력은 뭔가? (링크, 텍스트, 파일, 없음)
- 출력은 어디로? (Notion, Slack, 파일, 화면)
- 피해야 할 케이스가 있는가?

대화에서 이미 패턴이 보이면 (반복한 작업, 여러 번 실행한 것) → 직접 추출해서 이미 작성

### 2단계 → 이미 작성

위 구조대로 이미 작성 후 사용자에게 보여줌.
"이렇게 만들었는데, 빠진 게 있거나 다르게 하고 싶은 부분 있어요?" 확인.

### 3단계 → 테스트 (간단히)

실제로 쓸 것 같은 프롬프트 2~3개 제시:
"이 스킬에 이렇게 부르면 잘 동작할 것 같아요. 직접 써보고 이상한 부분 알려주세요."

테스트 프롬프트 예시 형식:
```
테스트 1: "/recap https://notion.so/..."
테스트 2: "/recap https://slack.com/..."
```

### 4단계 → 개선

피드백 기반으로 수정. 개선 방향:
- 자꾸 빠뜨리는 게 있다 → 단계를 더 구체화
- 결과물 형식이 이상하다 → 출력 형식 항목 추가
- 트리거가 안 된다 → description 수정

---

## 기존 스킬 개선 시

1. 해당 스킬 파일 읽기
2. 문제가 되는 부분 파악 (사용자 피드백 기반)
3. 수정 후 before/after 보여주기
4. 사용자 확인 후 저장

---

## 현재 스킬 목록 확인

`.claude/commands/` 폴더의 파일 목록을 보면 현재 스킬 현황을 알 수 있음.
새 스킬이 기존 스킬과 중복되지 않도록 먼저 확인.

---

## 스킬 작성 후 체크리스트

- [ ] `name` 필드가 파일명과 일치하는가
- [ ] `description`에 트리거 조건이 명확한가
- [ ] 실행 순서가 구체적인가 (모호한 단계 없음)
- [ ] 출력 형식이 정의되어 있는가
- [ ] 500줄 이하인가
- [ ] CLAUDE.md 스킬 목록 업데이트 필요 여부 확인
